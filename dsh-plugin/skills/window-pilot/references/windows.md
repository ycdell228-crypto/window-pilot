# Windows operations

The exact HWND/process identity and binding belong to this connection. Bind related dialogs separately after explicit selection; same PID alone does not prove a relationship. Default access is read-only. Left click, additional mouse actions, control patterns and real foreground input have separate grants and require the human-task purpose. Caller-supplied purpose is not proof of human authorization; operator policy may impose additional restrictions.

Acquire exact-window ownership before new evidence, renew the lease as needed, and release it at the end. Fresh evidence is single-use and expires in 30 seconds; inputs invalidate old observations across connections. Failed or empty reads give no input permission. Use `get_window_state(include_text=true)` for native Edit value/selection state. Control IDs belong to one observation; never infer them from a previous tree or use bare numeric indices.

Capture only the bound client area. Preview coordinates must be converted with `image_to_client_scale` to physical client pixels. No desktop, region, monitor or alternate-backend fallback. `observe_controls` intentionally omits values; bounded text from `get_window_state` is provider-scoped, password-filtered and may be truncated or unsupported.

Mouse operations use local messages, not the real pointer. Double-click requires receiver CS_DBLCLKS; do not emulate it with two singles. Scroll targets the verified point-hit child; steps are signed 120-unit increments, vertical positive up, horizontal positive right, -10..10 excluding zero. Background drag always refuses before dispatch.

`set_value` replaces the entire value. Standard Win32 Edit uses WM_SETTEXT with fresh native edit state; `type_text` uses EM_REPLACESEL at the observed caret/selection and does not replace the whole value. WPF set_value is refused. Background `press_key` always returns BACKGROUND_KEY_BACKEND_UNAVAILABLE/not_sent: no SendInput, PostMessage, text substitution or foreground fallback. Inspect each node's `background_actions`; `unverified` is not certification of background safety. Control actions recheck identity, runtime/tree/state/geometry; no SetFocus, global input or password input.

Use `foreground_action` only when the human's task explicitly permits real desktop input and the binding grants `observe_and_foreground`. It needs exact ownership, fresh evidence, safe target-owned UIA focus and held-input checks. Reject password or unverified focus. External input stops dispatch; release only input owned by this action, never a known external same-key hold. Report monitor/cleanup failures. This executor's gate is not desktop isolation and does not isolate other executors or humans.

`launch_app` requires the authorized administrator executor and a human-named local executable with authorized arguments/cwd. No clipboard, arbitrary commands, per-call elevation or host elevation. Executables are trusted code, not sandboxed; never use interpreters for unrequested commands. The unique request_id is consumed even for an unknown outcome: do not generate a new ID to retry. PID/exit is not readiness; find and observe the actual window. Fixture tools own only their fixtures; they provide no game workflow or scheduler.
