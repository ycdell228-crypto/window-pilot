# 第二项：后台动作的前台目标拒绝

2026-11-08，首项用户验收并存档后继续；用户随后明确“第二项验收通过，存档并继续”，本项随本次提交本地存档。未部署或推送。

## 行为

- `click`、`control_action` 在申请派发之前核验前台窗口，目标本身、目标同进程的其他前台窗口、相同 root-owner 窗口族均拒绝后台输入。无法取得有效前台 HWND/PID 也拒绝，不转前台兜底。
- 同进程保护是保守边界：例如用户正在同一应用的另一个窗口工作，该应用的后台窗口也拒绝输入。不同应用的正常前台活动不因此拒绝。
- 鼠标每条消息前重新检查；中途用户切入目标应用，不再发送后续消息（包含未发出的释放消息）。已有部分派发继续使用既有未知故障和禁止重放机制，不自动补发。
- UIA 在 Python 入口、worker 验证阶段和实际 Pattern 调用前检查；提供方返回后再检查。调用前拒绝是 `not_sent`，调用后发现目标成为前台则返回 `unknown`，锁存既有共享故障，不宣称动作成功。
- 原只读观察仍可用；明确选择的 `foreground_action` 保留其独立授权与前台检查，不受后台拒绝规则代替。

## 验证

命令：`CI=1 WINDOW_PILOT_NATIVE_TESTS=0 python scripts/test_runner.py`，普通44通过、0失败、12跳过入口。新增测试覆盖前台目标、同进程其他窗口、未知前台、按下后切入目标时停止释放并锁存故障，以及 UIA 入口拒绝时不启动输入 worker。

对四项派发测试做过反证：仅在测试进程内把保护函数替换为空操作，四项全部失败；磁盘实现未移除。此为受控 Win32 边界测试，不是假称人工真实切窗。

共享 worker 的只读原生回归8通过、0失败（20.814秒），仅自有窗口；另以实际前台 HWND/PID 做只读拒绝核验，不读取正文、不输入用户应用。证据位于 `.local/foreground-guard-*.txt`，不入Git。

## 尚未证明

派发前检查与操作之间仍有竞态，不能原子阻止用户在两者之间切窗；UIA 提供方也可能在调用内自行激活窗口，事后检查只能停止后续操作，不能撤销已发生的激活。尚未验证所有后台动作的真实应用行为、实际硬件切窗以及完整并行工作任务。本项是拒绝规则及停止机制，不能标记整个后台验收底线已达成。
