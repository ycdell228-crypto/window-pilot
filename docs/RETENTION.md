# 截图与审计保留

配置缺省时也启用以下上限，配置写在所选config文件的顶层retention字段；示例见[config.example.json](../config.example.json)。配置在服务创建时读取，修改后应空闲停止/启动并重新连接，不自动重放任务。

| 对象 | 默认策略 | 执行时机 |
|---|---|---|
| `.local/frames/<frame_id>.png` | 最多512张、总计256 MiB、最长30天；先清最旧 | 每次保存新截图 |
| `.local/audit.jsonl` | 当前文件最多8 MiB，另保留4个编号归档 | 每次写审计 |
| `.local/app-launches/` | 不自动删除 | 跨连接、跨重启的启动去重凭据 |

所有frames上限同时生效；一张原图超过总大小上限时不落盘，observe仍返回预览和原图哈希，并以`evidence_storage.saved=false`与reason明确报告。磁盘删除不删除内存中的新鲜观察，也不清除输入故障或自动恢复。时间保留是按访问清理，不是后台定时器；服务空闲时不会自行唤醒删除。

审计按完整UTF-8 JSONL记录轮转为audit.jsonl.1至.4。降低配置上限或首次遇到大于上限的旧文件时，保留能容纳的最近完整行并移除多余编号归档；历史证据会按此策略删除，需长期保留时应先由操作方另行归档。单条记录超过配置上限时明确报错，不静默截断字段。max_bytes至少1024，backups为1至100，其余上限为正整数；错误配置拒绝启动。

清理只处理标准生成帧名及audit.jsonl的数字归档，不递归清理其他文件、不跟随符号链接或junction。同一执行端连接共享锁；独立执行端不应共用同一数据目录。未知文件和额外人工备份不计入上述额度。配置、启动回执、安装备份、外部验证截图均不属于自动清理范围。
